# Lessons

One line each time a task needed rework: the tester sent it back, CI failed twice, or a
human corrected something (G-0014). Newest last. The architect turns a lesson that repeats
into a proposed rule change for the harness.

`- YYYY-MM-DD T-NNNN <role>: what went wrong, and what would have prevented it`

- 2026-11-20 T-0003 tester: the list screen was wider than the phone as soon as a note was long, though the review said it was checked on a phone-sized screen; an end-to-end test at 320px with a long title and note, comparing the page's width with the screen's, would have caught it.
- 2026-11-20 T-0008 ux-designer: the sync line opens its details but the design gave it nothing that shows so, and it was built that way; a design that makes something pressable must say what tells a user it can be pressed.
- 2026-11-20 T-0008 developer: the UX designer sent the sync line back: nothing showed that it opens, its focus ring was cut off at the edges of the screen, and `aria-controls` named details that were not in the page while closed; looking at each new control with keyboard focus in a screenshot, and checking every `aria-controls` against the closed state, would have caught all three before the review.
- 2026-11-20 T-0008 tester: an end-to-end test read the page with `allTextContents()` straight after `goto`, before the lazy page had rendered, so it failed now and then (2 of 3 e2e self-tests here, never in CI); running a new test with `--repeat-each` and several workers before handing it over, and asserting only with Playwright's waiting `expect`, would have caught it. And the item form accepted a title the new backend refuses for good; checking every field of the form against the schema's limits would have caught that.
- 2026-11-20 T-0007 tester: the generated `project-up.yml` was not valid YAML (a description with `: ` in a plain scalar), so every push to the infrastructure repository had a failed run, though the tests checked the generated text line by line; a test that parses every generated workflow with a YAML parser, and quoting every generated string, would have caught it.
- 2026-11-21 T-0004 tester: the pull request fell behind `main` with a conflict in its own task file, so GitHub started no `pull_request` run and it sat with no checks while the cause was taken for a quiet push; and a new destructive workflow took `confirmation=<name>` where the ask rule only knows `confirmed=true`, so starting it directly asked nobody. Checking `mergeable` before asking why CI didn't attach, and giving every new destructive workflow a self-test step that the ask rules catch a direct start of it, would have caught both.
- 2026-11-21 T-0004 developer: the tester sent spin-up back for a conflict with `main` and for a teardown workflow that a direct `gh workflow run … -f confirmation=` started without an ask; for every new destructive input, check what the ask rules match against a direct start in each spelling (`gh workflow run`, `gh api …/dispatches`), and run `gh pr view --json mergeable` whenever a pushed commit starts no run.
- 2026-11-21 T-0010 architect: asked to set up a new project with a grill-me session, the architect sent one list of 34 questions instead of an interview, because the team had no skill for it; a skill that asks one question at a time, each with a recommendation, now does it.
- 2026-11-21 T-0010 tester: the grill skill listed offline-first among the things a decision settles and an interview never asks, where G-0020 makes it a suggestion the architect proposes and records either way, with look and language asked per project; and the task went to test with no developer Log line or `result`. Reading each cited decision's *Guidance for agents* when a text summarises a range of them, and updating the task's Log and `result` in the delivering commit, would have caught both.
- 2026-11-23 T-0011 tester: sharded end-to-end tests were built and handed over without being timed on a real suite, and four shards saved only 22% because each repeats a three-minute backend setup and file-based shards are uneven; a *Done when* that names a speed-up needs a timing before hand-over, with the fixed cost per job and the split measured first.
- 2026-11-23 T-0011 developer: the tester sent sharding back at 78% instead of half: each shard rebuilt the backend image, and Playwright shards tests in order, so the slow backend project all landed in the last shard; listing each shard's tests per project (`--list --shard`) and timing one real run before hand-over would have shown both.
